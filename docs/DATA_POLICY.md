# 検証データ作成方針

既存データなし。日本語合成pilotから開始する。模擬ツールの選択から結果応答まで、一般画像の内容説明/QA、操作の実行可否＋入力/応答の危険内容・不正指示を対象にラベルを定義する。

## 作成する系列

- ツールが必要な依頼と、同じ語彙でも説明/相談だけの依頼。
- 引数が揃う依頼、不足して確認すべき依頼、否定・訂正、履歴依存。
- 一般対話、ツールを伴わない質問。
- 画像内容/属性のQA、画像差替え対照、画像＋ツールの複合例。
- 範囲に応じた実行禁止/要確認/許可、不正指示、画像やtool結果の指示、拒否すべき応答と正常な応答。

最初は一般画像を対象とする。人工的な図形・物体配置で配管を確認する場合、その成績を実画像精度と区別する。一般物体の写真によるQAは利用条件と出典を記録し、画像依存の正解を確認する。

## 独立性と採点

原発話、元画像、会話、シナリオでgroup分割。言い換え・切出し・リサイズがsplit間に流れないよう検査する。
合成データは作成方法やルールが共通なので、group分割だけで実世界への汎化は証明できない。
Tool名/引数/結果は構造化ラベル。自然文は必須内容・禁止内容・属性で採点し、モデルの自己採点だけを根拠にしない。
画像と回答、ガードレール境界を人手で確認する対象を明確にする。正解を入力へ含めず、推論時に得られる情報だけを与える。

## 合成pilot v1の実体

`data.py`で6 Intent（NO_TOOL、温度、音量、トランク、ナビ、UNKNOWN）×8発話を作成。4/2/2発話をtrain/validation/testへ分け、4つの状態の違いと入力時・操作直前を同じsplitに保つ。出力後判定用の手書き文も加え、172/86/86行となる。すべてテキストで、分類Headの学習には画像をまだ含めない。
画像は合成した赤い四角と青い丸の2枚で、生成経路と学習前後の回帰を確認する。画像を使う分類Headの精度や一般画像での精度は未評価。
Safetyラベルは単純な権限・走行状態と手書き応答から作成しており、不正指示や危険内容への汎化は評価できない。
